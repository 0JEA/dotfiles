# Marigold: moving the desktop off Tokyo Night

**Date:** 2026-08-07
**Status:** implemented

Replace the Tokyo Night palette with **Marigold**, a warm, saturated orange scheme, across every
themed surface on the machine.

### Why `cyan` and `magenta` stayed cool

`blue`, `cyan` and `magenta` are wired to terminal ANSI `color4`, `color6` and `color5` in
`kitty.conf.tera`, *and* to the primary UI accent in waybar/wofi/tmux/hyprlock. Turning all three
orange would have collapsed hue distinction in `ls`, diffs and syntax highlighting. Keeping two
cool anchors preserves legibility while the desktop still reads warm, because the background,
foreground and primary accent all are.

The slot *names* are historical and no longer describe their hue. Renaming them would mean editing
all seven templates, so the values changed and the names did not. This is documented inline in
`config.toml` so the next reader is not misled.

### Why `bright_black` is `#75665a`

The first draft used `#5c5148`, which measured **2.33:1** against `bg` and failed. `#75665a`
measures **3.26:1**. All other slots measured 4.25:1 or better, with `fg` at 14.67:1.

A crude manhattan-RGB check flagged red-vs-primary and yellow-vs-primary as too close. Rechecking
in CIE Lab showed the closest pair is red vs primary at **ΔE 26.7**, comfortably above the muddy
threshold of 20. The manhattan flag was a false alarm and no hue was changed because of it.

## Architecture change: `hypr/colors.conf`

`hyprland.conf` is deliberately **not** templated — it holds monitors, keybinds, `exec-once` and
input config, and matugen deletes anything a template omits. That is the exact failure that had
already eaten starship's `scan_timeout` and tmux's `allow-passthrough`.

Instead, a new colors-only file is generated and sourced:

- `theme/templates/hypr-colors.conf.tera` → `~/.config/hypr/colors.conf` (symlinked into the repo)
- `hyprland.conf` ends with `source = ~/.config/hypr/colors.conf`, sourced last so it wins
- the `col.*` lines were removed from the inline `general {}` block

Because the generated file contains nothing but colors, there is no non-colour setting to lose.

## Surfaces

**Regenerated by matugen (7):** kitty, waybar, tmux, wofi, starship, lazygit, hyprlock — plus the
new hypr colors. One file edit drives all of them.

**Hand-edited (62 hex replacements):** dunstrc, `paper-hud.py`, `paper-zathura-hud.py`,
`path_pills.sh`, `starship_path.sh` (decimal `R;G;B` format), `apply-theme.sh` fallback, imv
config (bare hex, no `#`), and the caps lock overlay strip.

**nvim:** kept `tokyonight` and injected the palette via its `on_colors` hook rather than switching
schemes. Verified `on_colors`/`on_highlights` exist at `tokyonight/config.lua:6-7` before relying on
them. This keeps every LazyVim integration and makes the editor background *exactly* the terminal
background — a different colorscheme would leave a visible seam, since gruvbox-material's darkest
base is `#1d2021`. Cost: the palette is duplicated by hand in `plugins/example.lua`, the only place
it is not driven by `config.toml`.

**GTK:** was never set up on this machine at all — no `~/.themes`, no `settings.ini` symlinks, no
`sassc`, gsettings on light `Adwaita`. Installed `Gruvbox-Orange-Dark` (`-t orange --tweaks black`).
This is the one surface that cannot match Marigold exactly; the palette is authored upstream.

## Verification

- Contrast and ΔE computed for every slot, not eyeballed
- Re-theme is a byte-identical no-op for kitty/tmux/starship/waybar, so `apply-theme.sh` no longer
  silently reverts preserved settings
- All four previously-lost settings survived a real `apply-theme.sh` run
- nvim `Normal` background reads `#1a1614`, matching the terminal exactly
- Live Hyprland borders read `eeff8c42 eefabd2f 45deg`
- GTK3 resolves `gtk-theme-name=Gruvbox-Orange-Dark` with `prefer-dark=True` in a real Gtk.Window

## Known gaps

- GTK is approximate, not exact
- The nvim palette is a hand-maintained duplicate and can drift
- `paper.frag.tmpl:317` still names `#c0caf5` in a comment explaining luma; harmless
- `claude/.claude/agents/doc-writer.md` still lists the Tokyo Night palette; out of scope
- Any nvim plugin hardcoding colors outside tokyonight's highlight groups will stay Tokyo-ish
  until spotted
